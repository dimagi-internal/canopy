tenant filter, so a denied `?agent=` lookup 404s instead of returning `200 []`.

### #416 — calibration half shipped

Root cause turned out to be deeper than the issue described. Every `tool_result`
block carries `is_error` — the harness's own verdict — and `extract_tool_calls`
was discarding it, so `friction_signals` re-derived failure by grepping the result
prose. That makes the *subject* of a result indistinguishable from its *outcome*.

Measured on 36 ACE turns, all counted as friction: a `PASS cchq_connect_features …
OAuth connection … configured` doctor line (both `failures` AND `auth_friction`),
a `tsc exit: 0` build whose release URL contained `-404-`, a `{"status": 200}`
response, and reading `apps/api/auth.py`.

Fix: keep `is_error` and believe it, with strong markers (traceback, `exit code
[1-9]`, `fatal:`, `panic:`) still counting on a zero-exit call so a `|| true`-wrapped
failure isn't lost, and absent-flag transcripts falling through unchanged.

Result: `failures` 403 → 198 (−51%), `auth_friction` 161 → 33 (−80%).

**Left open deliberately**, for two distinct reasons — residual noise with a
different root cause (results that are *content* rather than an outcome: file
reads, Drive listings, JSON blobs, some carrying no `is_error` at all), and the
lifecycle-taxonomy half (phase halt, resume boundary, upstream outage, deferred
self-heal, pluggable per agent), which is untouched.
