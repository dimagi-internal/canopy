# Module map

Where to start reading under `src/orchestrator/` and `plugins/canopy/`. Every module's first docstring line says what it is for: `python3 -c "import ast,sys; print(ast.get_docstring(ast.parse(open(sys.argv[1]).read())))" src/orchestrator/<name>.py`. ## Invariants and gotchas the code does not make obvious

- **`canopy_web.py` is the single source of canopy-web transport and auth.** Everything that talks to canopy-web resolves its token through `resolve_token`. The operator's workbench token (`~/.claude/canopy/workbench-token`) is never used in an agent's session: `agent_context_slug` decides "agent session" (`$CANOPY_AGENT` / `$CANOPY_AGENT_SLUG`, else the caller envelope's agent, else the cwd's agent repo) and `resolve_token` raises `AgentIdentityError`, as it does for a `CANOPY_WEB_PAT` that is just the operator's token. A human in an agent repo opts back in with `CANOPY_ALLOW_OPERATOR_IDENTITY=1` (warned); `agent_strict=True` (every DDD and walkthrough-share write) ignores even that. Writes name their workspace (`require_write_workspace`) and are read back (`confirm_landed`). stdlib `urllib` only. Contract: `docs/architecture/session-identity.md`.
- **`canopy_web_routes.py` is the route contract with canopy-web.** It reads canopy's source (AST) for every `(METHOD, path)` sent to canopy-web; `tests/test_canopy_web_routes.py` fails on a route canopy-web's vendored schema (`tests/fixtures/canopy_web_routes_schema.json`) does not serve; refresh with `python -m orchestrator.canopy_web_routes refresh-schema`. canopy-web vendors the `routes` output and fails a PR that removes a route canopy calls. A call it cannot read statically is `unresolved` and ratcheted per file.
- **`provenance.py` sends parent-turn headers on every canopy-web call** so a turn that a dispatch or script creates records the turn that started it; the parent TURN is the whole contract (canopy-web derives runner and host from it), so a new runner type only exports `CANOPY_TURN_ID` / `CANOPY_SESSION_ID`. Best effort: never fails a request. Contract: `docs/architecture/agent-client-rest-contract.md` § Provenance headers.
- **`inbox_rules.py` is the fleet's one inbound-email table and is vendored verbatim by canopy-web's runner.** Stdlib only. `tests/test_inbox_rules.py` pins its hash: edit it, re-vendor into canopy-web, update both pins.
- **`agent_email.py` takes its identity from the agent repo's `config/agent.json`**; the gog client defaults to the slug and one agent never shares another's client. `send` refuses without a `review_receipt.py` receipt keyed to the body.
- **`onepassword.py` is deliberately unreferenced** (kept for possible future use, no CLI surface); do not wire it into the credential path, the Canopy vault is the only credential source. `tests/test_onepassword_unreferenced.py` pins it.
- **`act_as_cli.py`**: the act-as credential (`~/.canopy/act-as/<claude session>.token`, 0600) is used only by `act-as get|call`, never by `resolve_token` or the MCP helper; a fleet `always` rail blocks reading it. **`sign_in_cli.py`**: the PKCE verifier stays in the detached provider process, so canopy-web holds nothing.
- **`dependency_health.py`** checks external dependencies of an agent box (run by `agent_doctor`); **`llm_output.py`** parses a `claude -p` reply into the YAML the caller asked for: use it rather than re-parsing in a new gate. **`repo_evidence.py`** is stdlib + git only.

## Plugin (`plugins/canopy/`)

- `skills/` (`canopy skills list`), `commands/` (a command colliding with a skill name follows Pattern B: `docs/architecture/skill-authoring.md`), `agents/` (`ls` it).
- `agent-core/` — fleet process docs read at RUNTIME by the ~20-line stubs stamped into every agent repo (not under `skills/`, so they cost no skill-description budget), plus the shared hook bodies `gating_guard.py` / `gdoc_gate.py` and `gating-baseline.json`. Baseline deny rails are keyed by channel mount; canopy's `--session` PreToolUse hook resolves the SESSION's agent (`$CANOPY_AGENT_SLUG`, then `$CANOPY_AGENT`, then the agent repo under the project dir, else nobody) and merges baseline plus that agent's rails at call time, fail-closed if the baseline is unresolvable; with no agent only the channel-independent `always` rails apply. Agents register no gating hook of their own, and a local `config/gating.json` only ADDS rails (channel mounts plus agent extras); it cannot remove a baseline rail. A rail or process fix here reaches agents by `/canopy:update`, with no per-agent PRs.
- `mcp/` — TypeScript MCP servers (ESM, run via `npx tsx`, no build step; toolchain in `plugins/canopy/package.json`). `mcp/gws-server.ts` is **canopy-gws**, the domain-neutral Google Workspace server; it is NOT registered in `plugin.json` (agents use `gog` / `canopy gdoc`; register it when an agent env carries `GWS_*`). Its identity is the SESSION's agent, resolved at the first tool call through `canopy cred check` + `canopy cred env` (`mcp/gws/lib/session-identity.ts`); a human session, a broker refusal or a missing identity refuses every tool call, with no default-identity fallback. Offline vitest suites: `plugins/canopy/test/gws/`, run by `.github/workflows/gws-tests.yml`.
- `.claude-plugin/marketplace.json` lists **two** plugins: `canopy` (versioned with `VERSION`) and `canopy-web` (`plugins/canopy-web/`, just canopy-web's HTTP MCP server with browser sign-in). `canopy-web` versions on its own; `canopy version bump` does not touch it.

## hooks.json

`plugins/canopy/hooks/hooks.json` is the table of event to hook; read it for what runs when. Rules the table does not state:

- Every registered hook fires in **every** session where canopy is installed, the whole fleet, so each advisory hook is fail-open and stdlib-only.
- The four PreToolUse **guards** (`--guard` in `hooks.json`: gating, profile, one-shot, credential `--pre`) fail CLOSED: `hooks/python.sh` turns any exit but 0 or 2 into a block, and `agent-core/gating_guard.py` blocks on an unreadable payload or a crash and treats a missing or broken `config/gating.json` as every channel mounted. A guard that does not import under macOS's system python 3.9 therefore blocks every tool call; `.github/workflows/hook-compat.yml` (a required check) runs each guard under 3.9.
- `hooks/python.sh` picks a working Python 3 (`python3`, `python`, then the Windows `py -3` launcher, skipping the Microsoft Store stub).
- `caller_context.py` (UserPromptSubmit) injects who is asking from `~/.canopy/caller/<turn_id>.json` and leaves the `by-task/<task>.json` parent record `provenance.py` reads.
- `profile_guard.py` confines a CALLER's session to what its agent's read mode or host site allows; owner and admin sessions are untouched.
- Decide-guard is a per-person opt-in (`canopy decide-guard stamp --user`), never plugin-wide or in an agent repo.
- The repo-local guards in `hooks/` (`pre_tool_use_*.py`, wired by `.claude/settings.json`) guard canopy's own development: main-branch, plugin cache, PR merge, version bump.
