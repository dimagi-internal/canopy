# CLI reference

The CLI states itself: `canopy --help` lists every command, `canopy <cmd> --help` (and `canopy <group> <sub> --help`) gives its flags, defaults, exit codes and what backs it. This page holds only what `--help` cannot say: where commands live, who each family is for, and the cross-command rules.

## Where commands are defined

- `src/orchestrator/cli.py` — the `main` click group. It registers the group objects imported from the `*_cli.py` modules (`main.add_command(...)` block near the top) and defines a set of commands inline (improve, serve, analyze, brief, patterns, observations, proposals, skills, version, doctor, shareout, test-audit, harvest, project-history, issue, agent-publish, openclaw-harvest, cursor, ...). To find a command: `grep -n '"<name>"' src/orchestrator/cli.py`.
- `src/orchestrator/<name>_cli.py` — one module per larger family (`agent_cli.py`, `cred_cli.py`, `vault_cli.py`, `huddle_cli.py`, `thread_cli.py`, `checkin_cli.py`, `runner_cli.py`, `people_cli.py`, `slack_ingest_cli.py`, `act_as_cli.py`, `sign_in_cli.py`, `secret_cli.py`, `kb_cli.py`, `local_cli.py`, `workspace_cli.py`, `closeout_cli.py`, `decide_guard_cli.py`, `eval_cli.py`, `turn_cli.py`, `aws_cli.py`). The email/gdoc/gsheet/gslides groups live in `agent_email.py` and `agent_gdoc.py`.
- A command's docstring and its module docstring say what backs it; the engine is usually a sibling module without `_cli` (e.g. `agent_dispatch.py`, `project_dispatch.py`, `huddle.py`). Module map: `docs/architecture/modules.md`.
- Output convention: commands that agents or scripts consume take `--json-output` (or `--json`); read it rather than scraping text.

## Who each family is for

- **Used by an agent inside a turn** (identity comes from the turn, not from flags): `email`, `gdoc` / `gsheet` / `gslides`, `cursor`, `checkin`, `thread`, `huddle` (leader), `closeout`, `people`, `caller`, `turn`, `cred`, `secret`, `act-as`, `sign-in`, `slack ingest`, `agent mode`, `agent reply`. Procedures are in `plugins/canopy/agent-core/` (`turn.md`, `huddle.md`, `thread.md`, `checkin.md`, `deliverables.md`, `email-drafts.md`).
- **Used by a person to run an agent themselves**: `agent use <slug>` (one idempotent command; `canopy local use` is an alias), `agent google-login`, `agents connect`, `agent doctor`. Contract: `docs/running-an-agent.md`.
- **Used by an operator or a runner to make a machine runnable**: `agent prepare` (the one implementation every runner calls; `--runner` resolves credentials with the runner's token), `agent bootstrap` (its laptop twin), `agent env`, `agent runs-as`, `vault`, `runner`, `agent move`, `agent read-mode`, `agent sites`. Lifecycle: `docs/architecture/agent-setup-lifecycle.md`.
- **Used by an operator to hand work to another agent or repo**: `agent dispatch`, `agent turns`, `project dispatch|runners|turns`.
- **Maintainer tooling** (improvement loop, session analysis, plugin hygiene): `improve`, `analyze`, `brief`, `patterns`, `observations`, `proposals`, `serve`, `skills`, `version`, `doctor`, `structure-drift`, `test-audit`, `verify-findings`, `fleet-align`, `harvest`, `project-history`, `issue`, `openclaw-harvest`, `shareout`, `agent-review`, `create-agent`, `agent-publish`, `eval`, `decide-guard`. Releasing: `docs/architecture/releasing.md`; session analysis: `docs/architecture/session-analysis.md`.

## Rules that cut across commands

- **Dispatch means spawned, not worked.** A harness turn reaching `done` after `agent dispatch` / `project dispatch` / `huddle dispatch` means the session was SPAWNED; the command reports LAUNCHED (unverified). Check the outcome with `canopy agent turns`. A person working with an agent uses `agent use`, never dispatch (`agent_dispatch.py::local_use_note_for` prints the note). Build turn bodies through `agent_dispatch.py::build_turn_payload`; never hand-roll `runner_id` / `turn_mode` into a raw POST, which skips the dispatch stamp.
- **Who may set a turn's mode or pin a runner is canopy-web's call, not the CLI's.** `--mode auto` and `--runner` are refused server-side unless the caller holds the role (terms: canopy-web `docs/architecture/access.md`); `--as` only lowers the role and ends with the turn.
- **A project turn is not an agent turn.** It needs `--workspace`, needs a runner that REPORTS the repo (`capabilities.projects`, runner-reported and not settable from a client), and writes no board task. The preflight refusal is a fact: do not route around it. `project_dispatch.py::classify_runners` decides refuse versus warn (an asleep runner is `dormant`: warn and enqueue; never-heartbeated or retired runners block).
- **Session identity gates credentials.** `canopy cred check` exits 0 allowed / 3 refused / 2 no agent / 4 undetermined (`cred_cli.py::EXIT_*`). Credential commands never print a value, except the railed `cred env --runner --print-json`. A human session or a refusal never falls back to a default identity. Contract: `docs/architecture/session-identity.md`.
- **Email is guarded.** Send through `canopy email send` (never raw `gog gmail send`; agents carry a deny rail and a thin `bin/<slug>-email` shim). `send` refuses without a matching pre-send review receipt for the body (`review_receipt.py::require`; record one with `email review-receipt`). The JSON result's `thread_id` must be recorded by the caller. Each mailbox is routed to the SES backend or Gmail by canopy-web's `/api/mail/resolve`; an unresolved lookup falls back to Gmail loudly, SES is never chosen on a guess. Details: `docs/architecture/shared-gog-gdrive.md` § 3.
- **Google authoring is as the agent.** `gdoc|gsheet|gslides publish` author as the agent's Google account; a Doc the agent wrote must pass `gdoc check` before a turn hands over the link (`agent-core/gdoc_gate.py`, a fleet Stop hook). Details: `docs/architecture/shared-gog-gdrive.md` § 5.
- **`decide-guard` is opt-in and per person.** Its prompt is generated from `plugins/canopy/agent-core/decide_guard_examples.jsonl`; never hand-edit the wired JSON. Never stamp an agent repo: it would apply to everyone who runs the agent (`decide_guard_prompt.py::PLUGIN_WIDE`, `decide_guard_cli.py`).
- **`closeout` computes the verdict, the turn does not type it.** `closeout_cli.py record` exits 3 on INCOMPLETE and the Stop hook `plugins/canopy/hooks/closeout_guard.py` blocks an unattended "safe to close" unless the latest verdict is CLOSED (`closeout.py` module docstring).
- **Slack is read only with permission, through canopy-web.** `slack ingest` needs an approval in the channel or an explicit allow-list entry; the agent never holds a Slack token and the fleet baseline denies direct Slack history reads. `transcript` returns only what is new since the agent's last read unless `--all`. Skill: `slack-channel-ingest`; code: `slack_ingest_cli.py`.
- **`agent doctor` is machine readiness; `agent health` is work-state readiness** (open asks, unread inbox) for the agent's next turn (`agent_health.py`).
- **Version rule.** Anything under `plugins/canopy/` needs `canopy version bump` (it fetches origin first and bumps every file that carries the version); `version verify-bump` is what CI and the push guard run. Use the command, never edit the version files by hand.
- **Hidden commands are not API.** Commands marked `hidden=True` (`agent token`, `agent session-token`, `private-runner register`, `workspace connect`, `email owed`) are internals or aliases; do not document or rely on them.
- **Knowledge bases**: `canopy kb` build/pull/push/mcp; the engine is canopy-web's `canopy_kb` loaded by `kb_engine.py` (`build`/`mcp` need it installed, `push`/`pull` do not). Contract: `docs/knowledge-bases.md`.
- **Threads and huddles keep no local state.** canopy-web is the state; `huddle await` and `thread run` are foreground and resumable (exit 3 means run it again). Contracts: `docs/architecture/agent-threads.md`, `plugins/canopy/agent-core/huddle.md`, `plugins/canopy/agent-core/thread.md`.
